Ruta de Personajes

Guía de la API REST para administrar personajes a través de operaciones CRUD operados por llamadas HTTP.

GET

Listar personajes

GET /api/v1/characters?page=1&limit=10

Devuelve una lista paginada de personajes.

  • page: número de página, opcional, valor por defecto: 1
  • limit: número de registros por página, opcional, valor por defecto: 10

Respuesta esperada: un arreglo JSON con objetos de personajes.

[
  {
    "_id": "64d9a6ef2ebdfb8b7f3bb12f",
    "name": "Astra",
    "alias": "The Starfall",
    "description": "Personaje curioso con poderes astrales.",
    "species": "Humana",
    "age": 24,
    "weakness": "La luz solar directa",
    "photo": "https://example.com/astral.png"
  }
]
GET

Obtener personaje por ID

GET /api/v1/characters/:id

Busca un personaje usando su ID de MongoDB.

  • Parámetro obligatorio: id
  • Tipo: string
  • Ejemplo: 64b8c0d4d1b23a909f2e4c12

Si no existe, responde con 404 y un mensaje de "Character not found".

{
  "_id": "64d9a6ef2ebdfb8b7f3bb12f",
  "name": "Astra",
  "alias": "The Starfall",
  "description": "Personaje curioso con poderes astrales.",
  "species": "Humana",
  "age": 24,
  "weakness": "La luz solar directa",
  "photo": "https://example.com/astral.png"
}
GET

Buscar por nombre

GET /api/v1/characters/name/:name

Busca personajes por un nombre exacto.

  • Parámetro obligatorio: name
  • Ejemplo: /api/v1/characters/name/Astra

La búsqueda se hace con el campo name del documento.

[
  {
    "_id": "64d9a6ef2ebdfb8b7f3bb12f",
    "name": "Astra",
    "alias": "The Starfall",
    "description": "Personaje curioso con poderes astrales.",
    "species": "Humana",
    "age": 24,
    "weakness": "La luz solar directa"
  }
]
GET

Buscar por alias

GET /api/v1/characters/alias

Busca un personaje por su alias usando una cabecera HTTP.

  • Header obligatorio: alias
  • Ejemplo: alias: The Starfall
curl -H "alias: The Starfall" http://localhost:3000/api/v1/characters/alias

La cabecera alias se valida y se usa directamente para consultar el personaje.

POST

Crear personaje

POST /api/v1/characters

Registra un nuevo personaje en la base de datos.

Body esperado

{
  "name": "Astra",
  "alias": "The Starfall",
  "description": "Personaje curioso con poderes astrales.",
  "species": "Humana",
  "age": 24,
  "weakness": "La luz solar directa",
  "photo": "https://example.com/astral.png"
}
  • name: string, requerido
  • alias: string, requerido
  • description: string, requerido
  • species: string, requerido
  • age: number, opcional
  • weakness: string, opcional
  • photo: URL válida, opcional

Si el contenido es inválido, la API responde con 400.

{
  "message": "Character created successfully",
  "data": {
    "_id": "64d9a6ef2ebdfb8b7f3bb12f",
    "name": "Astra",
    "alias": "The Starfall",
    "description": "Personaje curioso con poderes astrales.",
    "species": "Humana",
    "age": 24,
    "weakness": "La luz solar directa",
    "photo": "https://example.com/astral.png"
  }
}
PUT

Actualizar completamente

PUT /api/v1/characters/:id

Reemplaza todos los campos del personaje indicado.

Debe enviar el body completo con la estructura del modelo.

{
  "name": "Astra",
  "alias": "La estrella fugaz",
  "description": "Nueva descripción completa",
  "species": "Humana",
  "age": 25,
  "weakness": "Temperaturas extremas",
  "photo": "https://example.com/astral-v2.png"
}

Si el ID no existe, la API responde con 404.

{
  "_id": "64d9a6ef2ebdfb8b7f3bb12f",
  "name": "Astra",
  "alias": "La estrella fugaz",
  "description": "Nueva descripción completa",
  "species": "Humana",
  "age": 25,
  "weakness": "Temperaturas extremas",
  "photo": "https://example.com/astral-v2.png"
}
PATCH

Actualizar parcialmente

PATCH /api/v1/characters/:id

Actualiza solo los campos enviados en el request body.

{
  "weakness": "Campos magnéticos fuertes",
  "age": 26
}
  • Útil cuando solo quieres cambiar un campo
  • Los otros atributos no se tocan
  • Si no existe el ID, responde con 404
DELETE

Eliminar personaje

DELETE /api/v1/characters/:id

Borra un personaje por su ID.

  • Parámetro obligatorio: id
  • Resultado esperado: mensaje de éxito y metadata de eliminación

Si el personaje no existe, responde con 404.

{
  "message": "Character deleted successfully",
  "data": {
    "acknowledged": true,
    "deletedCount": 1
  }
}

Resumen de respuestas

  • 200 OK: operación exitosa en GET, PUT, PATCH y DELETE.
  • 201 Created: cuando se crea correctamente un personaje.
  • 400 Bad Request: cuando el body o los parámetros no cumplen la validación.
  • 404 Not Found: cuando no se encuentra un personaje con ese ID, nombre o alias.
  • 500 Internal Server Error: error inesperado del servidor.

Ejemplo de respuesta exitosa

{
  "_id": "64d9a6ef2ebdfb8b7f3bb12f",
  "name": "Astra",
  "alias": "The Starfall",
  "description": "Personaje curioso con poderes astrales.",
  "species": "Humana",
  "age": 24,
  "weakness": "La luz solar directa",
  "photo": "https://example.com/astral.png"
}

Objetivo educativo

Esta ruta muestra cómo un backend con Express + MongoDB organiza una API REST. Aquí se practican conceptos clave como:

  • Rutas y endpoints
  • Parámetros en la URL
  • Cuerpo de la petición (JSON)
  • Validación con Joi
  • Operaciones CRUD
  • Manejo de errores con Boom
  • Modelo y servicio en capas
